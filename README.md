# 闸对

中文名：**闸对** · 前缀 `gatetwin` · 端口 **6500 / 11500**

## 骨架

**刷卡点装载 → 同卡进站出站成对物化 → 缺腿/异向/超时旁路 → 行程账与刷卡点互证**

皮：地铁/公交闸机刷卡。去皮是 **OD 成对管道 + 开腿态 + 旁路 + 行程贯验**，不是票务售票 CRUD、不是乘车码业务页、不是日结封账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6500
# 刷卡流 → 灌「成对样例」→ 看开腿账/行程账 → 再灌「缺腿超时样例」「出站孤儿样例」→ 行程贯验
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 刷卡点 | 带卡号/站点/方向/事件时的进出闸事件 |
| 开腿账 | 已进站尚未出站的在途开腿 |
| 行程账 | 进站+出站成对后的正式行程 |
| 旁路匣 | 缺腿超时 / 出站孤儿 / 重复进站等 |
| 行程贯验 | 成对刷卡 ↔ 行程笔数 ↔ 旁路命运互证 |

## 行程封印写闸（已落地 · 口径=版本追加）

已成对行程进入**封印**态。此后任何出站站/历时修正**不得原地改基行**，只能追加版本行：

- 基行 `行程账`（版本 1）只读；修正落 `行程版本`（版本 2、3…，恰一条 `是否当前=1`）。
- 主读 `/api/行程账` 与贯验共用 `取当前` 解析器——**主读出站站=当前版本**，两处同票。
- 装载重放对封印行程**只读**：内容一致命中，冲突**拒绝**并入旁路匣，绝不覆盖旧行。
- `BEGIN IMMEDIATE` + WAL + `行程版本(行程键) WHERE 是否当前=1` 部分唯一索引 → 封印与重放
  并发时串行，**不得双当前**。
- 封印记录基行摘要 + 版本链摘要；「重封」只滚链摘要，不改基行。

只读接口：`GET /api/行程封印?行程键=…`（行程键、封印态、主读出站站、拒绝/当前版本、valid）、
`GET /api/行程封印/版本`、`GET /api/行程封印/审计`。写接口：`POST /api/行程封印`（封印）、
`/改出站`（版本追加）、`/重放`（重放隔离）。

可区分口径：成对后改出站——甲（未改）主读出站站不变且**无版本行**；乙（改后）主读出站站为新值且**有版本行**。
